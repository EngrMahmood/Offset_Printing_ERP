What's New (July 2026)

  • Print Color is a master list (1, 2, 4, 1+1, …) for production — not free-text ink names.
  • Plate Inks (Cyan, Magenta, Yellow, Black, Special 1/2) are selected only on plate requests for the vendor.
  • Multi-set plates: sets are suggested from impressions ÷ machine plate life (default 25,000); quantity is total plates, shown as e.g. 16 (4 sets); override allowed; all sets issued to production together for now.
  • AWC # is unique per SKU/design — cannot be reused on another SKU (same SKU may reuse for repeat/remake).
  • Released Jobs: production can request plate replacement (damage) with reason and damaged inks; job may show Waiting for plate.
  • Plate cancel: designer can cancel open plate requests when plates are not required (visible as cancelled/archived).
  • Print passes: production entry supports multi-pass jobs; pass count is inferred from planning/print color/machine rules when not set.
  • Packing entry: dedicated packing production entry flow.
  • SKU master: designer layout syncs to SKU; incomplete recipes stay Draft; QC can approve/reject in readonly master entry; reopen requires a reason.
  • Machine master: Plate Life (impressions per set) is editable on Master Data.

0. Quick Access for Dropdown Corrections

  • If a wrong dropdown value is added (machine/operator/material/department/product type/print color), open Master Data.
  • Use Rename to correct spelling/name.
  • Use Deactivate for machine/operator when you want to stop future use.
  • Admin can add Print Colors (production patterns such as 1, 2, 4, 1+1).
  • On each machine, set Plate Life (imp/set) (default 25,000) for multi-set plate suggestions.
  • Old records remain safe for audit.

1. Job Card Entry (Planning Stage)

  • Job Card No: unique order number for tracking.
  • SKU: product code.
  • PO Number/Date: customer order reference.
  • Material: paper or board used.
  • Print Color: production colour pattern from master (for example 4 or 1+1). Not ink names.
  • Order Qty: customer required finished pieces.
  • UPS: pieces per sheet.
  • Wastage: planned setup/loss sheets.
  • Machine: planned machine for this job.
  • Production Tolerance %: allowed extra sheets over planned quantity.

2. Job Card Auto Calculations

  • Required Sheets = Order Qty / UPS
  • Total Planned Sheets = Required Sheets + Wastage
  • Tolerance Sheets = Planned Sheets × Production Tolerance %
  • Allowed Sheets = Planned Sheets + Tolerance Sheets

3. Planned Time Calculations (Auto)

  • Estimated Run Time (min) = (Total Impressions Required / Machine Speed per hour) × 60
  • Estimated Setup Time (min) = Total Colors × Machine Setup Minutes per Color
  • Estimated Total Planned Time = Run Time + Setup Time

4. Production Entry (Execution Stage)

  • Job Card: choose which job is running.
  • Machine: auto-picked from job card, but override can be used when needed.
  • Operator, Shift, Date: who worked and when.
  • Print Color: shown from the job card (production pattern, not plate inks).
  • Print Pass: for multi-pass jobs, select the pass being run. Non-final passes record impressions and waste; good sheets are on the final pass.
  • Impressions: total machine impressions done (limits apply per pass and overall).
  • Output Sheets: good sheets produced.
  • Waste Sheets + Waste Reason: reject sheets and reason.
  • Run, Setup, Downtime minutes: actual consumed time.
  • Downtime Breakdown: add multiple downtime categories with minutes for one production entry.
  • Use Packing Entry for packing-stage production records.
  • Use Released Jobs to request plate replacement when plates are damaged on the floor.

5. Repeated Production Entries (Same Job Card)

  • Planned minutes are auto-allocated from remaining planned time.
  • Remaining Planned Time = Job Planned Total - Sum(previous active production planned times)
  • Total impressions are cumulative across production entries for the same job card.
  • Total impressions are validated against Total Impressions Required plus Production Tolerance %.
  • If extra allocation is needed beyond remaining planned time, overrun reason is mandatory.

6. Dispatch Entry (Delivery Stage)

  • Job Card: select the job being delivered.
  • Dispatch Date and Dispatch Qty: what was delivered and when.
  • DC No: optional dispatch challan reference.
  • Job completion threshold is 95% dispatch ratio.

7. OEE Rules

  • Availability uses unplanned downtime categories only: breakdown, operator, other (summed across all downtime rows).
  • Setup and planned/external losses are tracked, but treated differently from unplanned losses.
  • Performance compares actual impressions against machine expected impressions from run time.
  • Quality compares good sheets against quality-impact total sheets.

8. Overrun, Short Close, and Wastage Decisions

  • Overrun Minutes = (Run + Setup + Downtime) - Planned Minutes
  • Overrun is planning/time variance, not auto-wastage.
  • Job completion at 95% dispatch does not auto-convert remaining 5% to waste.
  • Remaining quantity below 100% appears as Short Close and must be operationally reviewed (carry forward, cancel balance, or dispatch later).
  • Manager/dispatch can click Close Gap with reason, and that pending short-close quantity is moved into Closed as Wastage.

9. Shift & Machine Schedule Config

  • Effective From/To: set validity date range of this shift plan.
  • Net Shift Hours: real productive hours after breaks.
  • Machine Work Schedule checkbox:
  • Checked means machine runs that day/shift.
  • Unchecked means machine is OFF that day/shift.

10. Dashboard Module (How to Read)

  • Top KPIs: OEE, Availability, Performance, Quality.
  • Planning KPIs: Planned vs Actual minutes, variance, schedule utilization.
  • Trend and analysis: production charts, machine/operator ranking, downtime, shift comparison, Pareto, at-risk jobs.
  • Short-close KPIs: pending short close and closed as wastage.

11. Search & Ease-of-use Helpers

  • Production Entry includes a user-friendly job card search picker.
  • Dispatch Entry includes job card search.
  • Machine is auto-picked from Job Card in Production Entry.

12. Archived Records

  • Archived Records lets you view deleted Job Cards, Production, and Dispatch records.
  • Use the All view to see every archived entity type together.
  • Restoring a record reactivates it while preserving audit trace.

13. Daily Working Discipline (Recommended)

  • Planner updates Job Card with correct machine before release.
  • Production logs shift-wise data same day.
  • Dispatch logs delivery same day.
  • Manager reviews short-close and overrun reasons daily.
  • Shift config is updated when timing/working pattern changes.

14. Planning Workflow Reference

  • Step 1: PO Intake. Upload or manually enter PO data and classify each line as repeat or new SKU.
  • Step 2: SKU Master. Missing SKUs must be created and approved before planners can continue.
  • Step 3: Planning Jobs. Planning fields are completed and the job card is created.
  • Step 4: Approval. QC validates the job card and the production manager authorizes release.
  • Step 5: Production Scan. Execution starts only after the released job card reaches the shop floor.

15. PO Intake Routing

  • Repeat Route: PO Intake → Planning Jobs.
  • New SKU Route: PO Intake → Pending SKU → SKU Approval → Planning refresh.
  • The PO Inbox shows duplicate merge notes, missing master counts, and the correct next step for each PO.

16. SKU Approval States

  • Draft: Planner creates or updates SKU master data.
  • Pending Review: SKU waits for QC validation.
  • Pending Approval: QC has reviewed and forwarded the SKU for managerial approval.
  • Approved: Final master data can be used for PO matching and planning.
  • Rejected: Reviewer sends the SKU back for correction with comments.

17. Job Card Approval Flow

  • Planner submission places the job card into the approval trail.
  • QC approval validates specification, print color, and production readiness.
  • Production manager approval authorizes release to the shop floor.
  • Only released job cards should be scanned and used in production execution.

18. Print Color vs Plate Inks

  • Print Color (SKU master / planning / job card): production pattern from Master Data (1, 2, 4, 1+1, …).
  • Plate Inks (plate request only): ink separations for the vendor — Cyan, Magenta, Yellow, Black, Special 1, Special 2.
  • Ink chips never overwrite Print Color on the SKU or planning job.
  • Legacy free-text colour values still work and show as (legacy) until changed to a master value.

19. Printing Plates Workflow

  • Plate Queue and Plate Requests list open plate work (draft, sent, received).
  • Send to Vendor: vendor, set nos, AWC #, Print Color (if missing), Plate Inks, Sets Required, Plate Quantity.
  • Sets Required is suggested as ceil(planned impressions ÷ machine plate life). Default plate life is 25,000 impressions per set (editable on Machine master).
  • Plate Quantity is total plates (sets × selected inks), displayed as e.g. 16 (4 sets). Designer may override.
  • Receive from Vendor, then Issue to Production — all sets on the request are issued together (staged issue will come with supply chain later).
  • AWC # is unique per SKU/design. Same SKU may reuse it on repeat or remake; another SKU cannot use the same code.
  • Cancel Request: use when plates are not required; request is archived and shown under Cancelled / Archived and on planning job lists.
  • Replacement plates: from Released Jobs (production) with reason and damaged inks; job may show Waiting for plate while graphics works the request.

20. SKU Master & QC Master Entry

  • Job Process (Planner, SKU master only): Print + Pack or Cut & Pack (no printing). Planning jobs use this value with no override; change only via Reopen SKU / master sync.
  • Print Color (Designer): production pattern from master (1, 2, 4, 1+1, …). Required for Print + Pack; not required for Cut & Pack.
  • Other designer fields: layout (size, ups, sheets, AWC #, die cutting, plate set).
  • Designer layout fields from plate making sync into the SKU master when blank.
  • Incomplete recipes stay Draft until required fields are filled; planner submits for review.
  • QC can open master entry in readonly mode to Approve or Reject/Send Back (reason required).
  • Reopen SKU requires a reopen reason for audit; SKU and job name stay locked except for admin.
  • Changing machine or print sheet (and similar plate-impact fields) after plates exist shows a plate remake warning.
